# T7a History Repository Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline, one fresh final review.

**Goal:** Durable independent Git history next to each code worktree, lossless migration and recoverable SQLite index.
**Architecture:** Storage exports/restores scoped JSON tables; host checkpoints through a hardened bare Git backend with stable identity and three-way recovery. SQLite records checkpoint bases and retains pending writes.
**Tech Stack:** Existing Rust, SQLite, Git CLI, React/Tauri; no new service or remote API.
**Spec:** `docs/superpowers/specs/2026-10-30-t7a-history-design.md`

## Global Constraints

macOS only; English compact UI; local commits, no push; T8 untouched. Never adopt unrelated sibling data. Preserve scoped IDs and source bytes. Credentials remain local.

## Review Focus

- Crash between SQL and Git commits: retained pending data and deterministic recovery (tasks 1–2).
- Hostile/symlink sibling and Git config: reject without writing through it (task 2).
- Moved worktree and duplicate IDs: stable manifest identity, conflict before writes (tasks 1–2).
- Erasure resurrection: Git history purged and tombstone durable (task 2).
- Migration missing obscure record kinds/receipts: complete table round-trip and unrelated-scope isolation (task 1).

## Execution ledger

Ruling: bare Git with structured table JSON — avoids incidental checkout edits, at cost of using Git commands/UI to browse source history. SQLite is also a durable pending journal, not disposable until checkpoint verified. Existing branch retained for continuous authorized work.

Storage gate: three image tests and full storage/host suites pass; source JSON strings preserve exact bytes. Ruling: one state.json initially — simpler atomic recovery and auditing, with larger diffs than per-record files. Externally advanced history against nonempty SQLite fails closed instead of auto-merging.
