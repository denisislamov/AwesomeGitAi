# Selected commit before opening code — 2026-11-01

The Files scope selector previously depended on an active code tab, so selecting a commit in Git did not enable its file list. Workspace now publishes a separate selected-commit file context, including an explicit comparison base when chosen. Files can load CommitDetails and open the returned parent/target pair before any code tab exists. Root commits use Empty. Selecting another commit updates the list while preserving the editor; activating/opening code returns the list to that code comparison. Working changes and All files remain explicit modes. A later commit selection invalidates an earlier pending file open so its response cannot overwrite the latest navigation.

Detached Files uses the same shared context. Native reads are restricted to the exact published selected pair or active historical tab pair and repository scope; unrelated requests remain denied. Existing Git panel authorization is retained. Scrollbars now use 7 px width/height, themed thumbs and transparent tracks in docked/detached WebViews; non-WebKit browsers fall back to thin scrollbars.

Validation: two failing file-navigation tests and a failing native detached-read test reproduced the gaps before fixes.
